# Native 0.3.0 source update: plans are drafts

The draft-only source update `bdc5229` was based on
`bfde102d49ee8a2e857d8d574cbd1f44835d5638`. It changes the native compile
tool's promise and return contract. It does not include the separate unpublished
scheduling proposal, implement a host adapter, or make recipes executable.
The source update is published on Git main. It does not install or update an active runtime, create a release tag or upload a package.

Intent to Plan can still help structure a request and produce a plan. Its native
decomposition and noncompile callables retain their existing contracts. The
compile tool now clearly stops short of instructions another tool can run.

## Breaking changes for native callers

| Call or input | Earlier behavior | 0.3.0 behavior |
| --- | --- | --- |
| `idd_compile({})` or `idd.compile(decomposition_json)` | Could return successful raw YAML | Failed result with JSON `status: blocked` and `execution_ready: false` |
| Explicit `mode: draft` | No versioned draft-mode contract | Successful draft production returns `idd-compile-draft/v1` JSON, never bare YAML |
| Input schema | Mode was not required; extra properties were not explicitly rejected | The string `mode: draft` is required; extra properties and wrong types fail |
| Nonempty malformed decomposition JSON | Could silently use a different session plan | Failed result; no fallback to the session plan |

An omitted or default empty `decomposition_json` string intentionally selects
the current Grammar state in explicit draft mode. Whitespace and other nonempty
malformed JSON fail. Supply a complete JSON object when you want to inspect a
particular plan rather than the current session's plan.

Default rejection happens before session-state access or compilation. No mode
validates a host recipe, grants approval or executes work. Draft approval fields
are data, not permission.

## Migrate an inspection-only caller

```python
import json

result = await compile_capability(decomposition_json, mode="draft")
payload = json.loads(result.output)
if not result.success:
    print(payload["status"], payload["message"])
else:
    assert payload["schema"] == "idd-compile-draft/v1"
    assert payload["execution_ready"] is False
    # Inspect payload["recipe_yaml"] as data only.
```

For a tool call, use `{"mode": "draft", "decomposition_json": "..."}`.
`success: true` means only that the requested draft was produced. Existing
consumers must stop assuming a successful raw-YAML return. Do not pass the JSON
envelope or its embedded YAML to the recipes tool.

## What remains unchanged and unsupported

The compiler, grammar, parser, hooks, static recipes and existing compiler tests
are byte-identical to the public-main base. The low-level compiler APIs still
produce the legacy dictionary/YAML shape, including roles, approval metadata,
dependencies and output references. Their retained prototype wording is not
evidence of current-host compatibility.

The compiler still infers parallelism from instruction words. The exposed
four-case probe remains two passes and two failures: negated or descriptive
“parallel” can group dependent assignments. This update does not repair that
behavior or import the separate sequential-default scheduling proposal.

The inspected current host rejects legacy step fields. A future, separately
reviewed adapter must preserve roles, human approval, output references and
fork/join meaning and pass installed-parser and runtime fixtures. Dropping
rejected keys is not sufficient. This update supplies no adapter or host
acceptance result.

## Version, identity and evidence

The root distribution, tool package, `idd` bundle and capability artifact are
versioned at `0.3.0`. The base bundle already used `0.2.0`; the new pre-1.0 minor
identifies this breaking contract. Hook versions, Python imports, tool/module
IDs, bundle namespace, portable method and `amplifier-capability/v1` remain
unchanged. `idd-compile-draft/v1` versions the draft envelope, not the host schema.

The seven reviewed guard files remain unchanged. Available offline checks cover
the guard, noncompile mock isolation and existing fixture-free compiler/grammar
assertions. Those software checks do not establish genuine provider behavior,
host execution, outside-user usefulness or human learning. The follow-up complete offline pytest/async suite passes 297 tests and 39
subtests on Python 3.12.10 with the existing Amplifier dependencies and existing
pytest 9.0.2/pytest-asyncio tools. No dependency installation was needed. This
unit suite uses authored fixtures and fake providers, not a real provider or
current-host recipe execution.

Historical evaluation inputs and results remain preserved. The Git publication
does not run model/provider requests or native host recipes, create credentials,
change services, install the native tool or establish outcome benefits.
